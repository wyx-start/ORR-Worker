## 2. 只读权限不能只看 following 状态

Qoder 的理解“当且仅当 field_states[field].status == following 时只读”不成立。

当背景处于整组 follow 策略，受控字段即使正在等待来源、来源冲突、未绑定或值无效，也必须只读。否则用户会在背景直接输入，输入随后又被解析覆盖。

为避免 UI 重复实现模式逻辑，Codex 在只读解析视图中增加：

    background_conditions.field_states[field].editable: bool

这是派生的显示／写入权限信息，**不新增持久化条件，不写入配置补丁**。

| 策略／状态 | 字段权限 |
|---|---|
| 整组 follow | 全部受控条件 editable=False，包括 waiting／conflict／unbound；未继承字段仍按原规则编辑。 |
| legacy_ph | 仅 pH 按旧策略的实际控制关系决定 editable；其他条件独立。旧 manual 空值可编辑，不能因“缺值”被误判为跟随。 |
| independent | 独立条件 editable=True，允许补齐或修正无效值。 |

UI 消费 editable，不从 status 推导写权限。active 和 not_required 只说明当前换算用途；未启用的缓存可只展示保留记录，不能因此开放向 follow 独立缓存写入。已知 pH／温度差异仍需显示。

用户明确选择切到独立后，可以收集拟议独立输入；模式与值仍在同一次草稿中暂存，统一应用前不改变已应用条件。底层业务与 stage 校验继续兜底。

## 3. 有效 applied 视图同样允许同值消除

Qoder 的理解“仅 candidate 时做同值消除”范围过窄。没有草稿时，applied 本身也是当前有效解析结果。

| view_basis | 用于同值消除 |
|---|---|
| applied | 可以，使用其有效解析值。 |
| candidate | 可以，使用同一有效候选解析值。 |
| applied_fallback | 不可以；这不是待修正草稿的有效条件。 |

例如背景独立记录 pH=null、当前跟随有效 pH=13：无草稿时向此背景使用 pH=13 模板也应识别为无变化，不把 13 或其来源写进独立记录。模板改为 12 时，仍须明确切独立，否则整次拒绝。

同值消除不使缺项／冲突消失，也不删除用户明确的模式转换或“用当前有效条件建立独立记录”动作。fallback 下保留待修正输入；不得拿已应用快照冒充候选来消除输入。

其余理解保持接受：以 records 构建差异、多目标先完整构建再一次 stage、模式与值原子暂存、摘要与编辑输入分离，以及预设按实际写目标门控。
