# 任务：选择背景后，默认沿用对应样品的 pH

状态：用户已确认，功能与审核完成，交付版本 1.4.0。

创建日期：2026-10-15。基于版本：1.3.1。

确认及完成日期：2026-10-15。用户进一步要求完成后审核并上传 GitHub。

## 1. 用户需求与目标

用户要求：选择背景后，默认认为背景与对应样品具有相同 pH。

实现后的常规流程为：填写并应用样品 pH → 选择并应用背景 → 软件自动为背景采用该 pH，不再要求到背景文件中重复填写。先选背景、后填写样品 pH 也应正常联动。

这一默认规则来自用户指定的实验约定，界面和导出记录应明确标注“沿用样品 pH”，不能标成从文件中测得。

## 2. 当前行为与问题

- 样品和背景分别保存 pH，选择背景只建立文件关联。
- RHE 坐标下，背景需要用自己的配置换算电位；即使样品已填写 pH，背景为空仍会报错。
- 1.3.1 已显示具体背景名称，并提供“将关联背景加入应用范围”；用户仍需额外应用一次相同 pH。
- 背景可以被多个样品共用，不能简单采用最后一次绑定或最后一次编辑的 pH，否则会影响其他样品。

## 3. 默认规则

### 3.1 新绑定默认同 pH

在“确认并应用分组与背景”和“应用扫描与背景设置”两个入口，正式提交背景关联后，默认启用“背景 pH 跟随关联样品”。盘背景、环背景采用相同规则。

- 背景原本没有 pH，样品有有效且已应用的 pH：立即采用样品值。
- 背景原本为软件联动得到的 pH：根据当前全部关联重新计算，不采用最后一个样品覆盖其他样品的方式。
- 背景已有人工填写或项目保存的不同 pH：保留原值并显示差异，让用户选择“采用样品 pH”或“保留背景独立 pH”。不静默覆盖明确的实验记录。
- 背景已有独立 pH 且与样品相同：可直接使用，继续标注原来源；用户可切换为跟随模式以便后续联动。
- 自动识别出来但尚未提交的背景候选，仅显示预览；不能因候选出现就改写配置。

普通“背景为空 + 样品已填”的情况不增加确认步骤，默认联动直接生效。

### 3.2 样品尚未填写 pH

先绑定背景时，记录跟随关系并显示“等待关联样品填写并应用 pH”。

- 不自动填写 13、14 或其他通用值。
- 样品输入框中的草稿不参与计算；点击“应用实验参数”后才触发联动。
- pH = 0 是有效数值，不能按空白处理；非有限值不作为有效 pH。
- 采用实测 RHE 总偏移或“已是 RHE”方式时，保留现有规则：电位换算本身不额外要求 pH。独立的 K–L 同条件核对继续保留。

### 3.3 后续修改自动跟随

样品的已应用 pH 改变后，处于跟随模式的背景同步更新。后台和界面应使用同一套规则。

- 若由 13 改为 12，且所有已填写的关联样品均为 12，背景更新为 12。
- 若更新后出现多个不同 pH，进入冲突状态，不能继续用旧值或任选一个值。
- 跟随方向始终为“样品 → 背景”，不反向改写样品条件。
- 常用配置套用、批量应用和逐文件应用完成后，都要重新检查关联背景。

## 4. 共享背景与冲突处理

同一个背景文件同一时间只有一个有效 pH。以背景文件为单位管理跟随/独立模式，不能为不同样品偷偷赋予不同的背景 pH。

| 场景 | 处理方式 |
|---|---|
| 900/1225/1600 rpm 样品均为 pH 13，共用一个背景 | 背景采用 13，记录所有来源样品 |
| 多个关联样品只有一个已填 13，其他为空 | 背景可沿用已知的 13；未填 pH 的样品仍单独提示，不能反向补齐样品 |
| 样品 A 为 13、B 为 12，共用一个跟随背景 | 明确显示冲突、文件名和各自数值；依赖该背景的处理暂停，其他无关文件继续 |
| 同一个文件同时作为盘背景和环背景 | 去重计算来源，不能重复写值或按通道先后覆盖 |
| 背景有独立实测 pH 12，样品为 13 | 保留背景值并提示差异；用户按实际记录选择模式，不能自动改成 13 |

数值比较采用有限数值与合理的浮点容差，`13` 与 `13.0` 视为相同；容差只用于消除表示误差，不将有意义的 pH 差异合并。

冲突不通过复制文件、修改图例或临时隐藏一条关联来自动绕过。用户应修正错误配置，或为不同实验条件选择适用背景。

## 5. 切换、解除绑定和独立设置

- 更换背景：移除旧背景对该样品的依赖，并重新计算新旧背景的来源和状态。
- 解除某一个样品的绑定：若其他关联仍一致，背景继续跟随其他样品。
- 最后一个关联被移除：只清理该背景的自动派生 pH 与跟随来源，不把历史自动值当成独立实测值。人工值保持不变。
- 提供“独立填写背景 pH”选项；切换后停止自动更新，并明确显示当前数值来源。
- 同一背景被多个样品共享时，切换背景模式应显示会影响哪些关联样品，避免让人误以为只改当前一条曲线。
- 在背景配置中直接修改 pH 时，应明确转为独立模式；不能一边显示跟随、一边实际使用人工覆盖值。

## 6. 界面与提示

### 背景选择处

提交绑定后显示简短摘要，例如：

> 背景 Ar-5mv-beijing.txt：pH 13，沿用关联样品（2 个文件）。

背景 pH 为空且样品已填时，不再要求额外点击“将关联背景加入应用范围”才能获得相同 pH。该按钮仍可用于用户主动共同应用其他实验条件。

### 实验条件摘要与错误

- 条件表区分“样品自身缺 pH”“背景等待样品 pH”“共享背景 pH 冲突”“背景独立 pH 与样品不同”。
- 展开后可查看关联样品和已应用数值，必要时切换独立模式。
- 提示中列出具体文件和值，例如“A.txt：13；B.txt：12”，不只显示泛化的“请填写 pH”。
- 草稿未应用时，继续显示 1.3.1 的“修改尚未应用”提示。

## 7. 计算范围与边界

本任务自动联动的参数为 pH。参比类型、内充液、温度、参比相对 SHE 电位、实测总偏移、面积和收集效率继续按已有规则保存与使用，不能因同 pH 自动视为全部实验条件相同。

- RHE 理论换算仍需要适用的参比值和温度；pH 已联动后，缺参比时应准确提示缺参比。
- 不复制氧气/氩气标记或电解液气氛说明，避免把背景改成样品气氛。
- 不更改背景插值、扫描方向、不外推、盘环符号和科学计算公式。
- 不放宽 K–L 所选样品之间的条件一致性检查。该检查比较的是参与拟合的样品，背景联动不能修复样品之间实际不同的 pH、面积或扫描方向。
- 原始坐标预览继续可用。明确的共享背景 pH 冲突也应显示，不因切换坐标就被冒称已解决。

## 8. 保存、恢复与来源记录

拟为背景配置增加以下逻辑信息，字段命名可在实现时调整：

- pH 模式：跟随关联样品 / 独立填写。
- 跟随来源：关联样品 ID、文件名以及已应用 pH。
- 状态：有效、等待输入、冲突、独立值有差异、已解除关联。
- 实际生效的 pH 与来源说明；冲突时不能把任意一个值当作生效值。

参数 JSON、处理记录和 `.orrproj` 同时保存模式、来源和状态，确保恢复后能解释实际用了哪个值。具体样品/背景绑定不写入可跨批复用的本机常用条件。

旧项目恢复时保留原有 pH 和来源，不因升级自动覆盖。用户可以主动开启跟随模式；原有空背景选择/重新确认绑定后可以采用本任务的新默认规则。

所有背景绑定、样品 pH 应用、模式切换和文件移除应先完成一批配置更新，再统一解析依赖，避免批量操作中的临时先后顺序产生错误结论。改变实际生效参数或引入冲突时，使相关旧结果和导出失效；来源记录改变时至少刷新参数导出。

## 10. 验收用例

| 场景 | 预期 |
|---|---|
| 样品已应用 pH 13，背景无 pH，再选择背景 | 背景自动采用 13，无需额外填写 |
| 先选背景，再给样品填写并应用 pH | 应用后背景同步；草稿阶段不生效 |
| 样品 pH 为 0 | 正常继承 0，不提示空白 |
| 同 pH 的多个转速共用背景 | 一次得到统一背景 pH，记录全部来源 |
| 13 与 13.0 共用背景 | 不误报冲突 |
| pH 13 与 12 共用跟随背景 | 指出具体文件和值，依赖该背景的计算暂停 |
| 一个样品缺 pH，另一个已填 | 已填样品可以继续，缺值样品单独提示，不反向补样品 |
| 背景已有不同人工值 | 保留并显示差异，按用户选择决定模式 |
| 单独修改背景 pH | 明确转为独立模式，之后样品修改不覆盖它 |
| 更换/移除背景或样品 | 新旧依赖重算，没有遗留有效的自动值或旧结果 |
| 盘环共用背景，或分别使用两个背景 | 两种情况均正确联动、去重与检查冲突 |
| 保存并恢复新项目 | 模式、pH、来源和冲突状态可追溯 |
| 恢复旧项目 | 原有 pH 不自动覆盖；可主动开启跟随 |
| pH 已跟随但背景缺参比 | 明确提示缺参比，不再笼统提示缺 pH |
| 无关文件存在有效结果 | 其他文件可继续，相关旧结果按现有失效机制更新 |

实施时运行相应的核心、条件和界面回归，并用合成数据验证真实浏览器流程。当前仅编写任务文档，不需要运行计算测试。
