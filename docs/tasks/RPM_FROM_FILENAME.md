# 任务：从文件名自动识别转速

状态：已确认并完成，交付版本 1.2.0。

创建日期：2026-10-14。基于版本：1.1.0。确认及完成日期：2026-10-15。

## 1. 目标

批量导入数据时，根据原始文件名中的转速标记自动预填「转速/rpm」。例如 `CoPc_1600转.txt` 应填入 1600，`CoPc_900转_测试2.txt` 应填入 900。用户仍可在核对表中修改，最终确认的值供 K–L 分析使用。

沿用已有的背景、扫描提取、电位换算、RRDE 和仅绘图平滑规则。本任务改变转速识别及其记录，不改变计算公式。

## 2. 实施前的问题

实施前 `orr_core.default_config()` 只匹配文件名末尾、由分隔符引出的 2–5 位整数，可带 `rpm` 后缀：

```python
r"(?:^|[-_\s])(\d{2,5})(?:\s*rpm)?$"
```

因此现有 `O-0.1MNa-5mv-900.txt`、`O-0.1MNa-5mv-1225.txt` 可以识别，但 `1600转`、位于文件名中间的转速，以及 `RPM1600` 等写法不能完整覆盖。

## 3. 已实现的规则

### 3.1 输入范围

- 读取上传文件的原始文件名，先去掉最后的扩展名。
- 不读取文件夹名称，不扫描 TXT 数据正文或表头来猜转速。
- 修改「样品/图例」名称不会自动覆盖已经确认的转速。
- 第一版识别非负整数转速，不把小数的一部分误当整数。

### 3.2 明确标记优先

在文件名任意位置识别以下写法，支持数字与单位之间的空格，英文不区分大小写：

| 写法示例 | 预填 rpm |
|---|---:|
| `CoPc_1600转.txt` | 1600 |
| `CoPc_1600 转_测试.txt` | 1600 |
| `CoPc_1600转每分钟.txt` | 1600 |
| `CoPc_1600rpm.txt` | 1600 |
| `CoPc_1600 RPM_测试.txt` | 1600 |
| `CoPc_RPM1600.txt` | 1600 |
| `CoPc_rpm=1600.txt` | 1600 |
| `CoPc_转速1600.txt` | 1600 |
| `CoPc_转速=1600.txt` | 1600 |

文件名中的单独“转”按实验命名约定解释为 rpm。避免把“转化”等无关中文词语当作转速单位。

### 3.3 保留现有命名兼容性

没有明确转速标记时，继续支持现有末尾 2–5 位裸数字规则：

- `O-0.1MNa-5mv-900.txt` → 900。
- `O-0.1MNa-5mv-1225.txt` → 1225。

这类值标为「末尾数字推测」，而明确单位的值标为「文件名明确标记」。裸数字可能是编号或短日期，因此仍需用户核对，不宣称识别结果已经得到实验确认。

存在明确标记时，不再用末尾裸数字覆盖它。例如 `CoPc_1600转_2.txt` 应为 1600，末尾 2 保留为其他命名信息。

### 3.4 歧义和无效值

- 多个明确标记给出相同转速：去重后正常预填，并保留匹配记录。
- 多个明确标记给出不同转速：留空，显示候选值和「转速冲突，请手动填写」。不取第一个或最后一个，也不退回裸数字猜测。
- 没有匹配：留空，不默认为 0 或 1600。
- 明确的小数转速：本任务第一版留空并提示，不截取小数部分。例如 `1600.5rpm` 不能变成 5 或 1600。
- `0转`：允许记录为 0，表示静止测试；K–L 保留已有「转速必须大于零」检查。
- 非 rpm 单位（如 rps）：不自动换算。

## 4. 界面与人工值保护

1. 新导入时预填转速，并在核对表中展示只读「转速来源」。详细说明包含匹配片段、冲突候选或未识别原因。
2. 人工修改后的数值优先，不因绘图、切换页面、保存项目或重复导入而被重新识别覆盖。
3. 增加「根据文件名补全空白转速」操作，便于处理已经导入的文件。只填当前空白值，保留所有非空值；有冲突时仍留空。
4. 完成识别后仍沿用「确认并应用分组与背景」核对流程。
5. 人工修改转速或补全转速属于科学配置变化，沿用结果失效机制，清空此前计算和导出，避免继续使用旧转速的 K–L 结果。

## 5. 默认分组

识别转速时，默认分组名移除明确转速片段，避免同一样品因转速不同而落入不同组：

- `CoPc_900转.txt`、`CoPc_1600转.txt` → 默认组 `CoPc`。
- `CoPc_900转_碱性.txt`、`CoPc_1600转_碱性.txt` → 默认组 `CoPc_碱性`。
- 现有两个 `O-0.1MNa-5mv-900/1225.txt` → 保持现有组 `O-0.1MNa-5mv`。

只移除转速片段并清理相邻多余分隔符，不自动删除浓度、扫描速率、日期、重复实验编号或其他实验条件。无法识别或冲突时不盲目合并分组。人工修改和已有项目中的分组继续优先。

## 6. 实现接入点

- 在 `orr_core.py` 增加独立、可测试的文件名识别函数，返回转速、来源、匹配片段、候选值、状态和默认分组建议。
- `default_config()` 在新文件导入时调用识别函数；纯函数不依赖 Streamlit。
- 在 `app_pages/import_data.py` 增加来源展示与仅补空白值的按钮，处理人工改值的来源记录。
- 逐文件配置增加识别来源/状态/匹配信息，并同步加入 `default_config()`，避免项目恢复时被过滤。
- 参数 JSON 和 `.orrproj` 保留最终转速及识别依据。
- 旧项目恢复时保留原有转速，即使为空也不自动改写；没有来源记录的旧值标为「项目保存值，来源未记录」，不能事后冒称是新算法识别的结果。
- 保持 schema=1 的向后兼容；只有确认需要改变项目结构时才另行设计迁移。

## 7. 验收用例

| 文件名 / 场景 | 预期 |
|---|---|
| `CoPc_1600转.txt` | 1600 |
| `CoPc_1600转_第2次.txt` | 1600，不把重复编号当转速 |
| `CoPc_1600 RPM_测试.txt` | 1600 |
| `CoPc_RPM1600.txt` | 1600 |
| `CoPc_转速=1600.txt` | 1600 |
| `O-0.1MNa-5mv-900.txt` | 900；旧规则兼容 |
| `CoPc_1600转_2.txt` | 1600；明确标记优先 |
| `CoPc_1600rpm_1600转.txt` | 1600；相同候选去重 |
| `CoPc_900转_1600转.txt` | 空白，显示冲突候选 900/1600 |
| `CoPc_0.1MNaOH_5mv.txt` | 空白，不把浓度或扫描速率当转速 |
| `CoPc_20261014.txt` | 空白，不把八位日期当转速 |
| `CoPc_1600.5rpm.txt` | 空白，提示不支持的小数写法 |
| `CoPc_0转.txt` | 0；K–L 拒绝使用零转速 |
| `CoPc_26.7rps.txt` | 空白，不自动换单位 |
| 人工把识别值 1600 改为 900 | 页面切换和项目恢复后仍为 900 |
| 点击补空白，其他记录已有 900 | 保留已有 900，只处理空白记录 |
| 保存/载入含识别信息的项目 | 最终值、来源、候选与分组保持 |
| 载入旧项目 | 保留旧值和分组，不重新猜测覆盖 |

数值测试应覆盖位置、空格、大小写、同值去重、冲突、数字边界和旧规则兼容。界面测试应覆盖预填、人工改值、补空白、结果失效及保存恢复。
