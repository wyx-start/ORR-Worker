# 工作计划：背景默认沿用样品实验条件

状态：**用户已授权实施；Codex 核心接口阶段完成，Qoder UI 接入及最终集成待交付。**实际完成范围、77 项核心验证与一个待接入 UI 用例见 [接口就绪说明](QODER_INTERFACE_READY.md)。尚未发布 GitHub。

日期：2026-10-21。基线：ORR Worker 1.6.0，已发布版本的自动回归为 157 项。本文件是新增工作的计划，不表示新增继承能力已经实现。

## 1. 目标与已确认决策

用户希望作为背景使用的文件，pH、参比等可以默认与对应实验样品相同，从而减少重复填写。

普通流程应为：**填写样品条件 → 选择背景 → 应用一次 → 绘图／分析／导出**。无需为了补背景参比或温度，再选择背景文件填写一次，也不增加单独的“同步背景”按钮。

```text
背景实验条件简化
├─ Q1 默认范围【已确认按建议】
│  ├─ 沿用样品的电位换算方式、pH、温度和参比整组参数
│  ├─ 实测 RHE 总偏移随对应方式生效
│  └─ 高级设置保留背景独立条件
├─ Q2 旧记录【已确认按建议】
│  ├─ 保留已有独立值和旧版仅 pH 跟随行为
│  └─ 提供一次“改为跟随样品”的入口，不静默升级
└─ Q3 共享背景【已确认按建议】
   ├─ 同一背景只有一套有效条件；不同转速可以共用
   └─ 已知条件冲突时列明原因，修改关联或独立设置后再处理
```

本轮只完成工作计划。整体确认后再实现、验证和更新使用／开发文档；本轮不改已发布软件。

## 2. 当前问题与改动范围

1.6.0 的 `background_ph.py` 只联动 pH。即使样品已设置参比、温度和换算方式，背景仍可能因缺这些条件无法处理，用户需要把背景加入应用范围或独立编辑。

本次把“仅 pH 跟随”扩展为有明确模式、来源和兼容规则的背景电位条件继承，接入现有统一草稿与一次应用。扫描识别、背景插值、盘环相减、K–L／RRDE 公式、仅绘图平滑及 Origin CSV 排布保持现有口径。

主要涉及：`background_ph.py` 或新的统一条件解析模块、`settings_draft.py`、`condition_ui.py`、`settings_editor.py`、`ui_shared.py`，以及 `orr_core.py` 的配置默认、背景依赖解析、参数和项目保存／恢复接口。

## 3. 自动跟随的字段与边界

### 3.1 跟随清单

| 条件组 | 字段／行为 |
|---|---|
| 电位换算方式 | `potential_method`，使用样品当前明确选择的方式 |
| pH、温度 | `pH`、`temperature_C`，保留有效 0 值和参数来源 |
| 参比整组 | 名称、内充液、`ref_V_SHE`、文献／标定来源及 `reference_preset_C`，作为完整方案继承 |
| 实测 RHE | `rhe_offset_V`；0 V 有效，只加一次总偏移，不再叠加理论 pH 修正 |
| 已是 RHE | 保持对应的零平移行为，不重复换算 |

参比方案不能从几个不完整样品拼装，例如从 A 取名称、从 B 取电位。来源说明文字不同，不应单独当成实际参比冲突。各方式未启用的历史缓存值保留，但不作为当前换算的有效输入。

“完整方案”指取得同一来源的整组快照，不新增参比名称或内充液必填要求。未记录的元数据保留为未知；理论 RHE 仍按现有有效参比电位、pH 和温度等实际依赖校验。

“跟随样品”是用户默认采用同条件的约定，不是从文件测得这些条件。摘要和参数记录必须标明来源。尤其“已是 RHE”包含背景输入电位也采用相同表达的约定；若背景文件仍是未经换算的原参比电位，应在高级设置中改为独立条件。用一句说明即可，不新增每次必点的确认框。

继续执行现有物理校验，例如 25 °C 参比预设不自动变成适用于其他温度的参比值。

### 3.2 不自动复制的内容

- **电解液／气氛文本**：现有 `electrolyte` 同时记录电解液、浓度和气氛。整体复制会把 Ar／N₂ 背景改记为 O₂ 样品；本轮保留背景原记录，不拆分字段，也不据名称猜测气氛。
- **面积、直径、收集效率 N**：背景按电流 A 扣除，这些样品分析参数不新增为背景必填项。
- **扫描规则／方向／手选段、通道、符号、转速**：按各文件自己的原始数据和映射处理，不复制样品的段编号或通道编号。
- **iR 开关、电阻和补偿确认**：按各文件独立的电流与补偿历史处理，不因继承参比条件一并覆盖。
- **环固定电位、材质、检测确认、文件身份与分组**：保留各自记录，不由跟随功能推定。

## 4. 模式、旧项目与人工值保护

### 4.1 新背景

- 新导入文件作为背景使用时，默认“跟随关联样品实验条件”；未选择背景时不自动建立关联。
- 新文件的软件初始 25 °C 等默认值不等于人工独立条件，不能因此阻止默认跟随。
- 跟随状态下，主区只读显示有效值和来源，不要求再填一套背景条件。
- 高级区选择“背景独立设置”后，用户可填写实际背景条件；独立值不再随样品变化。
- 公共条件编辑器选择背景、或向背景载入预设时遵守同一模式：跟随项显示只读有效值；需要主动改写时明确切到独立设置，模式和值进入同一草稿。不能接受输入后又被继承解析静默覆盖，也不能把该输入当成从未发生。
- 切换模式先进入草稿。明确应用后才改变有效条件；独立条件保留为可恢复记录，不能因切换而无提示删除。

### 4.2 旧项目及已有背景

- 缺少新继承模式字段的旧项目按兼容规则解释，不能直接套新文件默认值。
- 旧版仅 pH 跟随的背景继续仅 pH 跟随；参比、温度、偏移等保留原来的独立值。不能把原有 pH 自动联动冻结成独立值。
- 旧背景已有独立 pH 或其他人工值时保留，不凭“数值恰好等于样品”猜测它是继承值。
- 提供“改为跟随样品”操作，将整组切换加入同一草稿；列出受影响的背景、字段和关联样品，再用已有统一应用入口提交，不增加第二次科学提交。
- 升级过程中可以保留“旧版条件”兼容状态，界面说明清楚；不要求用户逐项重新确认才可恢复原项目。

## 5. 共享背景的解析规则

### 5.1 一套有效条件

同一背景文件无论被盘、环或多个转速文件引用，都只解析一套全局有效实验条件；盘环引用同一背景时来源去重。不按当前选中的第一个文件、最后编辑文件或调用顺序覆盖背景。

- 所有关联样品已知条件一致时，派生背景有效值，并记录来源样品。
- 转速差异不构成继承冲突；不因 900、1225、1600 rpm 需要重复填写背景。
- pH、温度等已知条件差异，或当前换算方式／有效参比方案／实测偏移差异，按字段列出文件与数值。
- 来源有缺项时不编造数值、不反向补样品。已知一致的值可用于派生；参比组只有完整、相容的来源方案才能继承，不能跨来源拼装。
- 未使用换算方式中保留的历史参比／偏移，不冒充当前有效参数造成冲突；真实已记录 pH 等实验差异仍需明确核对。

### 5.2 缺项、冲突与继续处理

- 缺值时显示“等待样品填写”；真正需要它的 RHE 处理才要求补齐。原始电位预览不新增无关必填项。
- 已知共享条件冲突时，不采用默认数值或首末来源绕过。依赖该背景的任务明确阻断；不相关文件继续。
- 用户可更换适用背景、修正关联样品记录，或明确为背景选择独立条件。独立模式保留实际背景参数，不自动修改样品。
- 合法但缺项／冲突的记录可应用并保存项目；计算／导出按实际依赖预检查。候选校验或任务预检查失败时保留草稿、不提交、不下载旧结果。
- 设置已成功提交后，若后续计算或文件生成失败，应保留已应用的新修订并说明任务失败；不能恢复旧结果，也不能将已生效设置重新标为未应用。
- 换绑、解除关联、移除文件后重新解析；只清理无来源的派生值，保留人工独立记录。跟随缺项时不能偷偷回退到过时的旧独立值。

## 6. 界面与一次应用

1. 选择背景后显示一句摘要，例如“背景：沿用本组样品条件 · pH 13 · 25 °C · Ag/AgCl”。有效值已解析时不再重复显示“请填写背景参比”。
2. “背景实验条件”统一组件代替单独的背景 pH 面板，普通区只显示跟随／独立／等待／冲突摘要；独立字段和兼容状态说明放高级区。
3. 修改样品条件、载入预设或切换背景模式后，都在候选副本中得到背景预览；不在页面渲染或逐字段输入时直接改已应用配置。
4. 继续复用“应用设置”“应用并计算／导出／保存项目”。不要求额外点“同步背景”，也不要求把背景手动加入样品应用范围。
5. 模式变化影响共享背景的全部关联样品，应显示目标范围。单个样品的局部编辑不能无提示地改写共享背景的独立条件。
6. 预设仍只携带允许复用的条件；不能夹带具体背景绑定、跟随模式或核对状态。载入样品预设后，已处于跟随模式的背景自然随最终候选解析。

## 7. 状态、导出和项目一致性

- 建立单一的背景条件解析入口，接入候选预览、实际处理、缺项提示、参数导出、项目保存和恢复；旧 pH 解析与新整组解析不能互相反复覆盖。
- 模式／状态和必要来源进入默认配置、合法性检查及项目恢复白名单；不只增加 UI 临时值。兼容旧 schema=1 项目，若确需改格式，应写迁移测试，不能依赖旧读取器碰巧保留字段。
- 继承后的有效值与独立记录分清，保存模式及来源样品 ID；恢复后仍能继续跟随后续样品修改。
- 参数记录包含实际使用的背景条件、继承／独立来源及冲突信息。完整 CSV 的背景电流与状态保持可核查，不能把推定条件标为文件实测。
- Origin 绘图 CSV 使用实际处理后的电位与电流；继承改变科学条件后，按现有规则清除旧分析／导出。颜色和平滑仍只影响显示副本。

## 8. 实施顺序与验收

| 阶段 | 工作 | 交付要求 |
|---|---|---|
| 1 | 明确继承字段组、模式与旧配置迁移；扩展纯解析器 | 来源去重、冲突明细、无输入修改副作用 |
| 2 | 接入候选、实际处理、项目和参数 | 预览／计算／保存／恢复使用同一有效条件 |
| 3 | 收敛背景条件 UI 和缺项提示 | 正常批次只填样品、选择背景、一次应用 |
| 4 | 自动回归、真实浏览器和文档 | 原有 157 项回归及新增针对用例通过，记录证据 |

新增验收至少覆盖：

1. 先绑定空白背景，再填样品 pH／参比／温度，一次应用即可处理；反向操作顺序得到相同结果。
2. 样品更新或载入预设后，背景在候选与已应用状态中分别跟随正确值；组合导出包含最后一次输入。
3. 理论 RHE、实测总偏移（含 0 V）、已是 RHE、原始视图均正确，无二次换算和多余必填项。
4. 参比整组继承，温度适用性校验保留，不从不完整来源拼出方案。
5. 同条件多转速共享、盘环来源去重、已知冲突、缺项、独立覆盖、解绑和换绑均有明确状态。
6. 旧独立值、旧仅 pH 跟随、手工参比及实测偏移恢复后不变；明确切换整组跟随只需暂存一次、应用一次。
7. Ar／N₂ 背景的气氛记录不被 O₂ 样品覆盖；面积、N、转速、扫描、通道、iR 和环检测记录不被继承改写。
8. 单独环图／未扣背景视图不因未参与背景或盘通道的无关条件新增阻断；参与横轴处理的实际依赖仍检查。
9. 失败无半更新、草稿不丢、旧结果不可下载；保存和恢复后模式、有效值及来源一致。
   候选／预检查失败与提交后任务失败分别验收；公共编辑器或预设直接编辑背景时，不出现“输入已接受但被跟随覆盖”的假象。
10. 真实浏览器对比旧操作：不再选择背景重复填写参比／温度；整个流程保留一次明确科学应用。

实现时使用合成数据和隔离测试服务，不改原始实验文件及本机预设。完成后更新 README、USER_GUIDE、PROJECT、CHANGELOG、VALIDATION 和本任务完成记录，再按用户后续指令决定上传。
