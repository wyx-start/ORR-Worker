# ORR Worker：Windows exe 发行与桌面前端改写计划

日期：2026-10-26。
状态：**已授权逐阶段实施、验收并上传 GitHub；M0 已通过，M1 待开始。** 进度见 [阶段记录](../migration/STAGE_LOG.md)。
目标：分阶段交付可以在 Windows 本机直接运行、最终无需浏览器的 ORR Worker 桌面版。

## 1. 执行路线与范围

按“冻结基线 → 过渡 exe → 提取共享应用服务 → 桌面最小完整流程 → 完整操作界面 → 分析与导出 → 稳定性 → 正式交付”的顺序推进。

- 最终前端拟采用 **PySide6 原生窗口**，图表继续使用 Matplotlib，复用现有解析、科学计算、背景解析和项目格式。
- 先提供自带运行环境的 Windows 目录式发行包。用户解压后双击 exe，无须安装 Python、执行命令或下载依赖。
- 过渡版保留现有浏览器界面；最终桌面版直接显示原生窗口。两者明确标识，不把“exe 启动浏览器”描述为原生桌面改写完成。
- 改写期间保留可用的浏览器版和已发布源码作为对照。桌面版全部验收通过前，不移除原有入口。
- 首批仍按约 10 个文件的本机工作流验证；不增加云端账户、服务器部署、自动更新或新的电化学分析方法。
- 本计划中的目录、类名和构建工具为拟定方案；各阶段开始时确定实际接口和依赖版本，不把拟定接口作为现成能力。

## 3. 全程保持的行为

### 科学计算与来源

- 内部电位、电流、面积和 K–L 物性单位及符号保持现状；rpm 到角速度的换算、盘环扣背景、iR 顺序、RHE 换算和模型异常判定不随界面改写改变。
- 新导入默认 SCE／饱和 KCl／25 °C、pH 13、5 mm 盘直径；RRDE N 默认 0.369，均允许修改并标为软件默认。SCE 参比预设继续限定 25 °C。
- 旧项目人工值、显式空值、缺字段历史状态及有效旧低电流阈值保留。不能用新默认修复未知历史记录。
- 平滑只作用于极化图显示及其绘图 CSV；K–L／RRDE 始终使用未平滑电流。异常数值不靠取绝对值、裁剪或改物性来消除。

### 扫描、背景与草稿

- A／B 自动规则逐文件判断最后完整支线；支持递增、递减与人工选段，不复制不同文件的段号。
- 背景仍支持盘环配对或分别指定，盘扣盘、环扣环；不同转速可共用背景，已知条件冲突明确定位。
- `follow`、`independent`、`legacy_ph`、独立缓存及字段 `editable` 权限完整保留；有效条件视图只读，不作为持久化补丁来源。
- 科学修改进入统一草稿，明确范围后一次应用；绘图单位、颜色等显示选项即时生效。保留应用并计算／导出／保存项目的组合操作。
- 批量结构非法或跨编辑域矛盾时无部分提交，输入保留；单文件解析或扫描失败不拖垮其他可用文件。K–L 仍要求全部所选有效转速参与。
- 不重新引入已删除的补充记录、重复盘环核对、低电流阈值控件、常用预设区或转速识别详情区；转速表格仍可直接手改，识别依据仍保存在参数和项目中。

### 项目与导出

- 第一阶段保持 `.orrproj` schema=2 写入及 schema=1／2 读取，不因更换前端升级格式。若确有新字段需求，另写迁移说明后再实施。
- 保留 Origin 绘图 CSV 的独立 XY 列组、完整处理 CSV、PNG、SVG、参数 JSON、ZIP 和分析项目；绘图 CSV 与当前显示数据一致。
- 参数中区分 `stored_config`、有效条件和实际处理快照。失败操作不能下载或保存上一轮的旧结果。

## 4. 分阶段任务

### M0：冻结基线与建立对照样本

**工作**

1. 核对当前源码、远端提交及尚未提交的本机修改，保存可恢复的基线；不重置用户工作区。
2. 从生成器建立合成样本与 schema=1／2 项目，包括多转速、双通道、共享背景冲突、空条件、错误文件和异常电流。
3. 记录每个用例的输入、参数、扫描段、有效条件、处理数据、模型结果、导出列与状态，形成可复用的数值对照集。
4. 明确目标 Windows 系统、位数、显示缩放与干净机器验收环境；未验证的系统不写成支持范围。

**交付物**：基线说明、功能对照表、合成对照集、待验证环境矩阵。

**完成标准**：基线回归可复现；能够用固定输入分别验证旧版和后续新前端，且不读取真实实验数据或本机预设。

### M1：交付过渡 exe，先消除安装 Python 的步骤

**工作**

1. 先做最小冻结启动试验，验证 NumPy／SciPy／pandas、Matplotlib、Streamlit 静态资源和下载组件能随包运行。
2. 为冻结环境设计明确的启动入口，解决现有 `sys.executable`／`python.exe` 假设；验证子进程不会递归启动自身。
3. 采用目录式打包，提供清晰的过渡版 exe、图标和错误提示；第一次运行不执行 pip，不要求系统 Python 或联网安装。
4. 区分程序资源目录和可写用户目录。运行状态、日志等不能写入单文件临时解包位置或只读安装目录；导出与项目仍保存到用户明确选择的位置。
5. 处理重复启动、端口占用、启动失败和明确退出。只管理本软件创建的进程，不关闭用户已有分析会话或其他服务。
6. 用无 Python 的干净 Windows 环境验证导入、绘图、RRDE、导出、项目恢复及中文／含空格路径。

**交付物**：`ORR Worker Browser.exe` 过渡发行目录、构建配置、依赖锁定文件、启动／退出说明、验证报告。

**完成标准**：用户解压并双击即可使用浏览器版，运行无需命令行或外部 Python；现有数据与结果语义不变。

**阶段边界**：先验证打包可行性，再投入完整过渡包。如果过渡打包需要大规模重写旧界面，应记录障碍和替代方案，优先推进 M2／M3 的桌面改写，避免长期维护两套启动系统。未通过干净环境测试不能标为可分发 exe。

### M2：提取不依赖前端的应用服务

**工作**

1. 将工作区状态、配置修订、草稿、拒绝输入、结果及导出描述，从 `st.session_state` 包装中提取为可独立调用的应用对象。
2. 统一导入、暂存、获取候选、应用、处理所选文件、分析、项目保存／恢复及导出准备等服务操作。继续调用现有纯业务模块，不另写一套计算公式。
3. 明确接口只返回数据、状态和错误，不调用 Streamlit 控件、Qt 控件、浏览器下载或操作系统保存对话框。
4. 把图形样式、绘图数据和 Figure 构建从 `ui_shared.py` 拆出。桌面端不能直接导入会强制设置 Agg 后端并加载 Streamlit 的整个模块。
5. 旧 Streamlit 前端通过轻量适配层消费同一服务，以其现有流程检查抽取是否改变行为。
6. 将核心、浏览器、桌面、构建依赖分开管理；原有开发安装方式保持可用。新核心／桌面服务环境不得因为导入服务而隐式要求 Streamlit。

**交付物**：拟新增 `application/` 服务模块、接口说明、旧前端适配、状态／事务测试及依赖分组。

**完成标准**：无需启动前端即可完成一批数据的全部处理与项目往返；草稿冲突、回退、来源、结果失效和实际快照与基线一致；旧前端回归继续通过。

### M3：做出可运行的桌面最小完整流程

**工作**

1. 用 PySide6 建立原生窗口，暂沿用“导入与设置、极化曲线、K–L、RRDE、导出与项目”的工作区结构。
2. 实现一条真正闭环：导入一个文件 → 核对／应用条件 → 选择扫描段 → 显示曲线 → 导出 CSV／PNG → 保存并恢复项目。
3. 用 Matplotlib 嵌入 Qt，验证中文字体、坐标、缩放、平移和图形导出；避免 Qt 与无界面导出的后端冲突。
4. 尽早生成桌面目录式 exe，验证 Qt 插件、图形资源、窗口关闭、打包路径和无 Python 启动。
5. 暂未迁移的功能明确禁用并说明，不以空白按钮或静态示意图冒充已经完成。

**交付物**：`desktop/` 最小应用、桌面 exe 试用包、实际界面截图、闭环测试记录。

**完成标准**：双击直接进入原生窗口，不打开浏览器；最小流程能在目标机器完整运行；尚缺功能有清单，不能宣称整体迁移完成。

### M4：迁移导入、条件、批量扫描与背景

**工作**

1. 实现约 10 个文件拖入、重复文件识别、错误原因列表，以及样品名、分组、用途、转速、背景的可编辑表格。
2. 将实验条件编辑做成集中面板，默认值直接显示，必填项标记；常用项直达，高级项按需展开，切换文件或范围不丢输入。
3. 实现当前组／全部样品／自选范围、批量扫描与背景预览、统一草稿和一次应用；全“保持”不能清空已有修改。
4. 实现逐文件扫描预览、完整段标识、人工段高亮与选择、盘环通道／符号／iR 等高级设置。
5. 实现背景条件状态与模式切换，按字段控制写权限；保留独立缓存、旧版 pH 兼容和模式切换中的无关草稿。
6. 用 Qt 表格模型管理数据；显示层只发出明确补丁，不直接修改持久化记录或有效投影。

**交付物**：完整桌面设置工作区、表格模型、扫描预览、条件和背景控件及相应交互测试。

**完成标准**：未识别转速可直接填写；错误文件不阻塞其他文件；多目标操作与单文件操作不互相覆盖；跨页、换范围及拒绝后输入保留；核心条件与扫描结果逐项对照基线通过。

### M5：迁移极化曲线、K–L、RRDE 和全部导出

**工作**

1. 迁移盘／环电流比较、单位、颜色、图例、坐标范围和仅显示平滑；设置布局围绕当前文件与当前结果组织。
2. 迁移 K–L 物性方案、分析区间、条件差异定位、明确计算入口及结果／异常表；不能默认跳过失效的所选转速。
3. 迁移 RRDE 收集效率、计算入口、产率／电子数图与异常原因；保留旧阈值使用、环检测确认状态和文件级失败说明。
4. 实现原生文件／文件夹保存对话框；优先提供绘图 CSV，图片和完整数据可分别导出，“保存分析项目”保持独立。
5. 保持共享绘图数据与统一导出构建，核对屏幕显示、Origin CSV、PNG／SVG、参数和实际处理快照一致。PNG 与 SVG 对照图形内容，不要求不同绘图后端生成逐字节相同文件。
6. 完整实现 schema=1／2 项目恢复、schema=2 保存、原始字节及来源保留；恢复后重新生成结果，不把旧导出当成新计算结果。

**交付物**：所有分析工作区、原生导出流程、项目读写流程及前后端数值对照报告。

**完成标准**：完整功能对照表无遗漏；已知答案、扫描行号、条件来源、异常状态和 CSV 布局通过；旧项目未知值不被默认覆盖；选定任务失败时不输出旧结果。

### M6：完善响应、保存与退出行为

**工作**

1. 将批量解析、处理、分析及较大导出移到受控后台任务；提供进度和明确的失败／取消状态，主窗口继续响应。
2. 工作线程只读取不可变任务快照；Qt 控件和共享状态在主线程更新。返回结果必须核对配置修订／任务标识，过期结果不能覆盖用户的新设置或进入导出。
3. 取消操作不得半提交科学设置、留下标为成功的半成品文件，或用旧结果替代取消结果。正式文件写入采用临时文件后完成替换。
4. 区分“未应用草稿”“已应用但尚未保存项目”“已有结果已过期”。关闭时如有未保存工作，提供保存、放弃和取消；保存失败保持窗口与输入，不静默丢失。
5. 核对重复启动、多窗口限制、项目替换、文件名冲突、只读输出目录、中文路径、显示缩放和错误日志定位。

**交付物**：后台任务控制、修订保护、文件写入与退出策略、异常恢复测试。

**完成标准**：一批约 10 个文件处理时能操作窗口；连续修改后只接受匹配快照的结果；取消、失败及关闭均不损坏现有项目或误标保存成功。

### M7：完整桌面发行与迁移验收

**工作**

1. 在固定 Windows 构建环境锁定 Python、PySide6、科学依赖和打包工具，形成可重复构建流程；首版仍采用目录式包。
2. 在干净目标机器上从解压到退出完整验证：无 Python、无需联网安装、中文路径、导入 10 文件、批量条件、背景冲突修正、绘图、K–L、RRDE、所有导出及项目恢复。
3. 执行双前端对照、核心／服务测试、Qt 交互测试和实际 exe 测试，记录耗时、包体积、运行内存及已验证系统，不预先承诺未测数字。
4. 原 277 项检查中的纯业务用例继续复用；Streamlit AppTest／浏览器场景分别保留为旧版对照，并转写成 Qt 等价场景。不能仅删除不适配新框架的测试来宣布全部通过。
5. 更新 README、USER_GUIDE、PROJECT、CHANGELOG、构建说明、验证与已知限制；提供可直接使用的 `ORR Worker.exe` 目录包和校验摘要。
6. 用户已授权每阶段验收后同步 GitHub 源码；形成可审查发行目录后再决定 Release 交付。只有通过桌面全部验收，才调整默认入口与浏览器版维护状态。

**交付物**：正式桌面候选包、构建配置、迁移和回退指南、全量验收报告、功能完成表。

**完成标准**：目标用户从下载到实际分析全程无需 Python 或命令行；最终版不用浏览器服务完成分析；所有必需功能和数值对照通过，项目与旧版本兼容范围写清楚。

## 5. 文件与架构安排

以下结构是实施建议，M2 时确定实际接口，不先移动全部既有文件：

```text
orr_core.py / background_*.py / settings_draft.py / batch_settings.py
    保留已验证的纯业务模块
application/
    工作区状态、草稿事务、任务快照、处理与导出服务、绘图构建
desktop/
    Qt 主窗口、表格模型、条件面板、扫描预览、图表和保存对话框
packaging/windows/
    过渡版与桌面版入口、构建配置、资源及可重复构建脚本
app_pages/、condition_ui.py、settings_editor.py、ui_shared.py
    迁移期间的浏览器前端和适配层
tests/
    原有对照、服务测试、Qt 等价场景、项目兼容与 exe 验收
```

约束：桌面层不能导入 Streamlit UI 模块；核心不能依赖 Qt。项目格式由共享服务统一处理，不能出现两个前端各保存一套不兼容配置的情况。

若再次与 Qoder 协作，由用户转交阶段任务文件；先明确本阶段接口和单一文件写入者，再接入。本计划不自动发送协作消息，也不把旧的 UI 文件归属约定直接套用于新架构。

## 6. 验收矩阵

| 场景 | 必查结果 |
|---|---|
| 全空／冲突转速列 | 可手填、人工值优先、原依据保留、项目往返一致 |
| 9 样品＋1 背景批次 | 批量方向／规则与配对背景正确，背景扫描独立，无部分提交 |
| 缺条件、共享冲突、独立缓存 | 状态和来源正确，等待不回退旧值，切换模式不丢无关草稿 |
| 项目与默认值 | schema=1／2 兼容；新默认明确，旧空值／人工值不覆盖 |
| K–L 已知答案 | 数值、角速度、物性单位、条件和异常判定一致 |
| RRDE 已知答案 | N、盘环符号、背景、阈值、产率／电子数及异常行一致 |
| 绘图与 Origin CSV | 独立网格、点数、单位、NaN 缺口和显示平滑一致 |
| 修改／计算／导出交错 | 使用同一明确修订；旧任务和失败操作不产生旧下载 |
| 干净机器与退出 | 无 Python 可启动；明确退出无自有残留任务；不操作其他进程 |

数值容差按已有独立正确答案和既有测试确定，记录比较依据；不能为让桌面版通过而事后放宽容差。

## 8. 技术依据
